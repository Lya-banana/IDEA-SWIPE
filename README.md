# IDEA SWIPE · 灵感划片

## 一、选题名称

**灵感划片（IDEA SWIPE）——基于卡片式交互与偏好学习的 AI 创意辅助工具**

## 二、痛点场景

在使用 AI 进行设计创意发散和头脑风暴时，AI 往往一次性输出大量文字和多个创意方向，用户需要花费较多时间阅读、理解和筛选，容易产生信息过载。

同时，传统对话式交互难以针对单个创意进行快速反馈，用户即使知道自己喜欢或不喜欢某个点子，也很难准确表达原因。随着对话不断深入，之前有价值的灵感容易被淹没，用户也难以逐步明确自己的偏好，并从大量创意中选出最满意的方案。

## 三、准备怎么做

设计一个结合 **AI 对话、卡片滑动、偏好标签和可视化决策** 的创意探索工具，将传统的长文本问答转化为更轻量、直观的交互过程。

1. **AI 创意生成：** 用户通过聊天框输入设计问题，AI 将生成的创意拆分成多张卡片，每张卡片呈现一个核心点子及其简要说明。
2. **滑动反馈与偏好学习：** 用户通过右滑（有点喜欢）、左滑（有点不喜欢）、上滑（非常喜欢）快速表达偏好，并为特别喜欢的创意添加标签或自定义理由。长按卡片可以屏蔽不感兴趣的标签，系统持续记录用户的选择。
3. **喜爱地图：** 将用户喜欢的创意汇总成可缩放、可浏览的可视化地图，突出显示“非常喜欢”的点子，帮助用户整体回顾、比较和发现自己的兴趣倾向。
4. **二选一创意收敛：** 通过两张卡片之间的连续比较，让用户逐步筛选创意，最终确定最喜欢的方向，同时保留之前积累的偏好标签，作为后续 AI 创意深化的依据。

## 四、期待效果

**从“被动阅读 AI 答案”转变为“主动参与创意探索与决策”。**

- **降低认知负担：** 通过单张卡片聚焦一个创意，减少长文本带来的阅读压力。
- **提高反馈效率：** 用直观的滑动操作代替反复输入文字，让用户更轻松地表达喜好。
- **帮助用户认识自身偏好：** 通过标签记录与喜爱地图，使模糊的审美和创意倾向逐渐清晰、可视化。
- **辅助创意收敛：** 借助二选一比较，降低面对大量方案时的决策难度。
- **促进人智协同：** 让 AI 不仅负责生成创意，还能根据用户积累的反馈辅助后续探索与深化。

最终希望探索一种更轻量、有趣、可持续反馈的 AI 创意交互方式，让用户不仅获得更多创意，也能更清楚地理解自己为什么喜欢某个创意。


# 使用方法


## 1. 最简单：无需安装

直接用浏览器打开 `index.html`，即可体验**本地演示模式**。输入任意课题会使用本地创意模板给出可判断的卡片；「校园闲置物品交换」含 10 张预制样例卡。它不是真实 AI 输出。

## 2. 接入真实 AI（可选）

需要 Node.js 18 或更高版本，不需要 `npm install`。在终端进入这个文件夹，输入：

```bash
export OPENAI_API_KEY='你的API密钥'
node server.mjs
```

浏览器打开 `http://127.0.0.1:3000`。网页会自动发现可用的服务端，并让聊天输入调用真实模型生成 10 张结构化创意卡。默认模型为 `gpt-4o-mini`，可以设置 `OPENAI_MODEL` 更改；可以设置 `OPENAI_BASE_URL` 接入支持 OpenAI Chat Completions 的兼容服务。

**安全提示：** API 密钥只放在服务器环境变量，网页代码不包含密钥。不要把 `server.mjs` 带着真实密钥公开部署。默认仅监听本机 `127.0.0.1`。

## 3. 交互清单

- 左滑：不喜欢；右滑：有点喜欢；上滑：非常喜欢，可挑选及自定义标签
- 长按卡片或右键：选择并屏蔽标签，阻止之后的创意卡出现该标签
- 支持键盘快捷键：← / → / ↑；二选一阶段可按 `1` / `2`
- 喜爱地图：网格式全局布局、紫色突出非常喜欢、缩放、平移、点击查看、标签筛选及编辑
- 二选一：赢家逐轮对决，完成后得到「最喜欢」的创意
- 数据：浏览器 localStorage 自动保存喜欢记录、屏蔽标签、会话、二选一进度
- 结果：可下载偏好 JSON 或创意概念 Markdown

## 4. 边界

当前为课程交互原型，不是部署到公网的正式 SaaS。AI 后端可选；无 API 密钥或调用失败时自动使用本地样例。偏好记录只保留在本机浏览器同一来源下，清理浏览器数据会清空记录。
